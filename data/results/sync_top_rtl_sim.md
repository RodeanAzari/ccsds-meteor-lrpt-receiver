# sync_top_rtl_sim

- **Commit:** `84859c45331e5afe8f0bab5fae9c0974dcaee50c`
- **Command:** `make sync-rtl-results`
- **Tools:** Python 3.14.4, NumPy 2.5.4, SciPy 1.18.1, Verilator 5.050, cocotb 2.1.0
- **Input:** synthetic, seeds 30-31 in tb/cocotb/test_sync_top.py via sync_chain.py (bit-true DDC output of OQPSK at 6 dB Eb/N0, 1 kHz offset + 30 Hz/s before the coarse estimate, 0.37 symbol timing offset, 20 ppm clock; AGC from gain 1.0). No real recording.

The synchronization chain RTL (`rtl/sync/sync_top.sv`) matches the model chain `rrc_fixed` → `agc` → `costas` → `timing` (`model/sync_fixed.py`) on every output. The input is the bit-true DDC output of what the receiver will see after the host's coarse estimate: OQPSK at 6 dB Eb/N0, 1 kHz off with a 30 Hz/s ramp before the estimate, 0.37 symbol late with a 20 ppm clock error. The loops start from reset, with the AGC at gain 1.0. The first run is 12,000 samples with random input gaps and an output ready 0.8% of the time. At that rate the output is slower than the chain makes samples (0.5 vs. ~0.56 per 62-clock RRC sample), so stalls propagate back through every stage. A first version with the output ready half the time never stalled the inner links: a planted AGC that ignored the Costas loop's tready passed it. At 0.8%, tying any of the three inner tready signals high (RRC → AGC, AGC → Costas, Costas → timing) fails the test. The second run measures throughput: 62 clocks per input sample, set by the RRC's time-shared FIR, 6.3× real time at 100 MHz. Each loop's pull-in and clamps are tested in its own block test, and the decode of the chain's output is in `sync_chain_rtl_decode`. Input is synthetic.
