# timing_rtl_sim

- **Commit:** `0e449531d347843affa8ae0aae2dfa86b2ad3a6e (with uncommitted changes)`
- **Command:** `make sync-rtl-results`
- **Tools:** Python 3.14.4, NumPy 2.5.4, SciPy 1.18.1, Verilator 5.050, cocotb 2.1.0
- **Input:** synthetic, seeds 16-18 in tb/cocotb/test_sync_timing.py (bit-true Costas output of OQPSK at 6 dB Eb/N0, 0.5 symbol timing offset, carrier centred; clamp test: 100 ppm clock error and limit = one ki step). No real recording.

The timing RTL (`rtl/sync/sync_timing.sv`, Farrow cubic resampler with the per-rail OQPSK Gardner detector) matches `model/sync_fixed.py` `timing()` on every output in three runs. The first is 16,000 samples of bit-true Costas output (OQPSK at 6 dB Eb/N0, carrier centred) starting half a symbol late, so every strobe begins on a transition, with random stalls on both sides. The loop pulls in within the run: the strobe eye ratio (mean |soft| / std |soft| over the last 2,000 outputs) ends at 2.08, against 1.48 for the same input with the loop gains set to zero. The test asserts that the no-loop baseline stays under its 1.9 threshold, so the check cannot pass on a dead loop. A first version of this test also had a 100 ppm clock error, which drifted the offset by 0.45 symbol over the run and aligned even the dead loop. The baseline guard caught that, and the lock run now has no clock error. The second run (8,000 samples, 100 ppm) sets the integrator limit to one ki step, so nearly every update saturates the integrator. The third measures throughput: outputs are produced one at a time, because each output's error sets the next position. That gives 8.86 clocks per input sample, 44× real time at 100 MHz. Planted bugs each fail: the detector always on the I rail fails all three tests, and the integrator clamp removed fails the clamp test only. Lock range and lock time against timing offset and clock error are Phase C measurements still to be made. Input is synthetic.
