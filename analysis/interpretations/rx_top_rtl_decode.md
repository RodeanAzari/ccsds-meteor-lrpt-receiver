The board top for Phase E (`rtl/top/arty_rx_eth_top.sv`: fpga-eth-core RX → `iq_udp_ingest` → DDC → `rx_chain` → `cadu_packet` + `stats_packet` → `pkt_arb2` → `udp_tx` → MII TX) decodes a synthetic recording from replay datagrams to CADU packets in simulation, bit-exact with the model. 1,137 datagrams (five CADUs of OQPSK at 6 dB Eb/N0, 151 kHz with a 30 Hz/s ramp) went in as MII nibbles back to back at the 100 Mb/s line rate, the fastest gs-replay can send (5.69× real time). The top was built with the NCO word the host's coarse estimate gives for this input (`scripts/board_rx.py freq-word`, checked against the test's constant) and the loop gains from the generated `rx_config_pkg`. Three CADU packets came out (frame 0 is lost to pull-in and the last frame's window runs past the input, as in the chain test), each one's header, status bytes and 1,024 CADU bytes equal to the bit-true model chain on the same raw input, each a frame that was sent; 501 stats packets came out between them, none cut or merged, with consecutive pkt_seq. The last stats packet counts every datagram through eth_rx, udp_rx, the ingest and the DDC with zero loss anywhere (no eth_rx overflow, no ingest gap), CADUs sent equal to the packets received, and the frame sync's counters equal to the model's. At line rate the eth_rx FIFO high-water mark was 1 byte: the ingest ring absorbed the chain's stalls, so the receiver keeps up with the fastest replay on this input. Planted bugs caught: the CADU counter counting stats packets, and the DDC ignoring the NCO word parameter. Not covered: the frame sync's slip and drop counters are 0 in the model here, so a swap between them would pass. Input is synthetic; about 5 minutes in Verilator (`make rx-top-rtl-results`, part of `make sim-full`).
