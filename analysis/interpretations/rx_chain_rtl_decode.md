These are the first CADUs out of the RTL on a signal: the whole receiver after the DDC (`rtl/top/rx_chain.sv`: sync_top → fec_soft_quant → fec_framesync → fec_viterbi → fec_frame_extract (NRZ-M) → fec_cadu (ASM check, derandomizer, RS ×4)) ran 203,897 DDC-rate samples (seven CADUs of OQPSK at 6 dB Eb/N0, 1 kHz off with a 30 Hz/s ramp before the host's coarse estimate, 0.37 symbol late, 20 ppm clock) with every loop starting from reset. Frame 0 is lost to pull-in. The frame sync found the other six, as the bit-true model does on the same input; five have complete windows (the last frame's window would run past the input). All 5,120 CADU bytes and all five status words (phase hypothesis, flywheel, ASM bit errors, per-codeword corrections) matched the bit-true model chain (`cadu_fixed.cadus_from_windows()` on `framesync_fixed.decode_windows()`), and each CADU is a frame that was sent, ASM included. RS corrected 0 symbols and failed 0 codewords: at 6 dB the Viterbi left no bit errors, so this run proves the RS path passes clean codewords in order, not its correction in the chain (that is covered block by block in `test_fec_cadu` and fpga-rs-core). The sink was held until the stall reached the chain's input, then held again 3,000 clocks after each release; `input_stalls` counts stalls of 2,000 clocks or more at the input. fec_cadu buffers a whole CADU, so at most one stall per waiting CADU reaches the input, and only while the input still has a full ring (two frames) to send: three here (CADUs 2–4). Planted bug caught in this version: the quantizer toggling I/Q without `tready` (byte mismatch after 3,084 bytes). The Viterbi reset at each window's end and the frame sync ignoring the Viterbi's `tready` were caught by the earlier bit-level version of this test and have not been re-run against this one. This proves the RTL decodes from DDC output to CADUs, not a frame-error rate; that belongs to a longer run or the hardware campaign. Input is synthetic. About 15–25 minutes in Verilator, so it runs in `make sim-full`.
