These are the first decoded bits out of the RTL Viterbi on a signal, not on prepared symbols. The Phase D chain (`rtl/top/rx_chain.sv`: sync_top → fec_soft_quant → fec_framesync → fec_viterbi) ran 145,642 DDC-rate samples (five CADUs of OQPSK at 6 dB Eb/N0, 1 kHz off with a 30 Hz/s ramp before the host's coarse estimate, 0.37 symbol late, 20 ppm clock) with every loop starting from reset. Frame 0 is lost to pull-in. The frame sync found the other four, as the bit-true model does on the same input; three of them have complete windows (the last frame's window would run past the input). All 24,960 bits the Viterbi emitted matched the model chain (`framesync_fixed.decode_windows()`), and after NRZ-M and the derandomizer, each of the three frames is a frame that was sent, ASM included, before RS: no bit errors to correct. The sink was held until the frame sync's ring filled and the stall reached the chain's input, then held again every 20,000 clocks; `input_stalls` counts the stalls of 2,000 clocks or more that reached the input (the count varies with the testbench's random seed). Planted bugs caught: the Viterbi reset at each window's end, the frame sync ignoring the Viterbi's `tready`, and the quantizer toggling I/Q without `tready`. The last one passed a four-frame version, where the stalls (which can't start before the ring fills, symbol ~49,000) fell after the last checked bit. This proves the RTL chain decodes from DDC output to frame bits, not a frame-error rate; that belongs to a longer run or the hardware campaign. NRZ-M, derandomizer and RS are still the model (Phase E). Input is synthetic. About 10 minutes in Verilator, so it runs in `make sim-full`.
